# Behavior Redesign Lane

문제 해결형만 탐색하면 문서 정리, 증빙, 비교, 업무 자동화 후보로 편향된다. `BEHAVIOR_REDESIGN`은 고통을 발명하지 않고 사람들이 이미 반복하는 행동의 결과와 의미를 바꾸는 후보를 찾는다.

공개적으로 확인되는 KYRO의 핵심 구조는 `러닝 경로 → 지도 위 영토 → 랭킹·친구·크루와 공유`다. 이는 성공을 보장하는 증거가 아니라, 평범한 기존 행동에 시각적 소유·진행·사회적 비교를 붙이는 설계가 실제 제품으로 구현될 수 있다는 calibration case다.

- App Store 기능 설명: https://apps.apple.com/kr/app/kyro-%EB%9F%AC%EB%8B%9D%EC%9D%84-%EB%8D%94-%EC%9E%AC%EB%B0%8C%EA%B2%8C/id6755943100
- 창업자·제품 소개: https://byline.network/2026/05/0512-5/

이 레인은 다음 계약을 사용한다.

1. 독립된 실제 사용자 원문 두 개 이상에서 이미 반복되는 행동이 확인된다.
2. 심각한 pain이나 workaround는 필수가 아니다.
3. 한 번의 행동이 즉시 보이는 결과를 만든다.
4. 다음 행동이 결과를 변화시켜 자발적 반복 이유가 생긴다.
5. 첫 사용자는 혼자서 가치를 얻고, 비교·공유·협동 루프가 설계되어 있다. 사람이 늘수록 실제 재미가 커지는지는 검증 가설로 남긴다.
6. 한 문장 또는 약 10초 데모로 변화가 전달된다.
7. 결제 의향, 장기 반복, 자산과 확장은 검증 전 가설로 남긴다.

Cold Critique가 “고통을 제거하지 않는다”는 이유만으로 이 레인을 차단하면 Code Arbitration이 false positive로 처리한다. 반대로 즉시 결과, 구체적인 놀이·반복 규칙, solo value, 데이터 접근, 10초 전달성, 설계된 social loop가 없으면 `VALIDATE_DELIGHT`를 통과하지 못한다. 네트워크 증폭과 실제 자발적 공유는 통과 전에 증명할 사실이 아니라 7일 행동 실험에서 측정할 가설이다.

7일 실험은 일회성 신기함을 성공으로 세지 않는다. 10명 중 4명 이상이 7일 중
5일 이상 기록하고, 3명 이상이 다음 주에도 계속 사용을 요청하며, 2명 이상이
요청받지 않고 결과 카드를 공유해야 한다. 공유받은 사람의 실제 유입을 확인하고,
재사용 이유 인터뷰에서 “다음 결과가 궁금해서” 돌아왔는지를 별도로 기록한다.
‘재생성 또는 공유 2명’처럼 반복과 공유를 합친 지표는 이 계약을 통과하지 못한다.

`WILD_BET`은 위 조건을 아직 충분히 증명하지 못해도 실제 행동 근거가 하나 있고 최종 validation plan이 14일·설정 예산 이내의 수동 샘플이나 짧은 영상 실험이면 보존한다. 비용 판정은 아이디어 생성 단계의 추정치가 아니라 저장된 validation plan의 기간과 예산을 기준으로 한다.
